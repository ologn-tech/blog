The **V3link Arducam** is a popular multi-camera solution designed primarily for **Texas Instruments development boards**. But what if you want to use it with a **Rockchip RK3566** platform?

This was exactly the challenge I faced, and after some experimentation, I successfully got it working. In this post, I'll walk you through the complete setup process, from hardware connections to software configuration.

---

## The Challenge

The V3link Arducam system uses the **DS90UB960** deserializer, which is typically paired with TI processors. The RK3566, while powerful, has a different architecture and requires careful routing of the camera data pipeline.

## Hardware Setup

The V3link Arducam connects to the **EM3566 Board**, which provides 4 lanes of CSI camera interface. To interface with the DS90UB960, I used an adapter board to connect 2 cameras from the EM3566 to the 4-lane CSI0 port of the DS90UB960.

## Sensor Configuration

Configuring the sensor pipeline is crucial for proper operation. The data flow follows this path:

**Sensor Link Path:**

```
imx219 → ds90ub953 → ds90ub960 → csi_dphy0 → mipi_cs2 → vicap → isp_v0
```

Each component in this chain plays a specific role:
- **IMX219**: The camera sensor
- **DS90UB953**: Serializer (at the camera end)
- **DS90UB960**: Deserializer (at the processor end)
- **CSI_DPHY0**: Physical layer interface
- **MIPI_CS2**: MIPI CSI-2 interface
- **VICAP**: Video capture unit
- **ISP_V0**: Image Signal Processor

---

## Multi-Camera Routing with Media Controller

One of the key challenges with this setup is routing multiple cameras through the system. We have **4 cameras** that need to be processed, which requires **4 virtual channels**.

Fortunately, the RK3566 supports 4 virtual channels in `rkcif_mipi`. However, there's a limitation: this configuration only works with **raw images** and cannot use 4 separate ISPs for 4 cameras because the RK3566 has **only one ISP**.

### The Solution

To work around this limitation, I decided to merge all 4 camera feeds into a single frame after passing them through the ISP. This approach allows us to:
- Process all cameras through the single ISP
- Obtain properly colored images (instead of raw)
- Display all 4 camera feeds simultaneously

This requires careful configuration of the media controller (`media-ctl`) to properly route the video streams.

While the V3link Arducam was designed for TI boards, it's definitely possible to use it with Rockchip RK3566. The key is understanding the data pipeline and properly configuring the media controller to route multiple camera streams through the single ISP.
